# AGENTS.md

PokéCal is a dependency-free, browser-first ES-module web app: a Pokémon lookup page (`index.html`), move catalog (`moves.html`), two-Pokémon battle calculator (`battle.html`), SP builder (`builder.html`), matchup overview (`matchups.html`), interactive Speed tiers (`speed.html`), and tournament teams (`teams.html`). No build step for the app, no npm dependencies; full catalogs in `public/*.json` are generated by sync scripts, and the slim browser catalogs in `public/web/*.json` are derived from them.

## UI quality policy

For UI changes, read and follow `DESIGN.md` and `docs/ui-quality-workflow.md` before editing. They are the authoritative project design and verification policy. Use the project-local Impeccable skill in Operate mode (refinement for cleanup, new-work for redesign) as the primary process and the project-local Vercel Web Interface Guidelines as a supplemental checklist. Generic upstream guidance must not override PokéCal's product truth, teal identity and shared lookup-style navigation, semantic and Pokémon type colors, system-font choice, precise data-source labels, or dependency-free architecture.

## Commands

Requires Node.js 22 (the MCP Worker and the permission-model sandbox for Showdown parsing need it). No `npm install` needed for the app; `npm run test:mcp`/`test:all` need `npm ci --prefix mcp --ignore-scripts` first.

```sh
npm start                      # static server at http://127.0.0.1:4173 (PORT / SERVE_ROOT env to change)
npm test                       # app suite: node --test "test/**/*.test.js" (no MCP deps needed)
npm run test:mcp               # MCP Worker suite (mcp/test; needs mcp deps)
npm run test:all               # everything via plain node --test
npm run test:server            # scripts/serve.mjs tests
npm run test:battle            # battle-order, damage, speed tests
npm run test:builder           # threat, builder-state, speed-line, bulk/break/cross-check tests
npm run test:catalog           # battle-state, catalog, identifiers, pokemon, stats, ui tests
npm run test:data              # sync/parser/merge/data-loading tests, incl. NCP, sync utilities, validation, fail-closed syncs, web catalogs
npm run test:damage            # test/damage.test.js only
npm run test:pokemon           # test/pokemon.test.js only
npm run sync-data              # regenerate public/*.json (Showdown incl. Champions mod at the pinned commit + PokeAPI, needs internet)
npm run sync-champions-data    # overlay Limitless Champions usage (run sync-data first)
npm run sync-champions-spreads # overlay Smogon ladder SP spreads (run sync-champions-data first)
npm run sync-ncp-spreads       # overlay NCP curated Champions sets (needs only sync-data; independent of the usage/spread overlays)
npm run sync-all               # all four syncs in order, then build-web-catalogs
npm run build-web-catalogs     # derive slim public/web/*.json and MCP public/mcp-catalogs/*.json from public/*.json (run after any sync)
npm run validate-data          # check public/*.json metrics; add -- --baseline <dir> for the shrink check
npm run stage-site             # stage the GitHub Pages site into _site/ (pages, src/, public/icons, public/web)
npm run bump-showdown          # move scripts/showdown-pin.json to the latest Showdown master (-- --commit <sha> / --ref <branch>)
```

Every sync script accepts `--allow-shrink` to skip only the max-shrink check (minimums still apply) when a legitimate upstream change shrinks data by more than 25%.

## Architecture

`src/` has three layers — `engine/` (pure battle math, no DOM/fetch), `data/` (loading, parsing, usage), `ui/` (DOM controllers) — plus shared identifier/i18n modules, locale catalogs, and `src/styles.css`. Data files must not import from `ui/`; `ui/` may import `engine/` and `data/`. See ROADMAP.md "Target code structure" for the authoritative layout and rationale.

- Seven static HTML entry points: `index.html` -> `src/ui/lookup-page.js` (lookup), `moves.html` -> `src/ui/moves-page.js` (move catalog), `battle.html` -> `src/ui/battle-page.js` (calculator), `builder.html` -> `src/ui/builder-page.js` (SP bulk/break points), `matchups.html` -> `src/ui/matchups-page.js` (one-on-one KO race against top usage, laid out as a sticky set sidebar plus "Common sets" / "Beyond the usual sets" tabs, with one results list filtered by outcome, opponent search and a List / Turn grid toggle; analysis in `src/data/matchup-analysis.js`, rare-choice theory sets in `src/data/uncommon-sets.js`, rarely used Pokémon in `src/data/niche-threats.js`), `speed.html` -> `src/ui/speed-page.js` (Speed tiers), and `teams.html` -> `src/ui/teams-page.js` (tournament teams). All share `src/styles.css` and load the slim catalogs from `public/web/*.json` (`src/data/data.js`, `src/data/limitless-teams.js`). The full `public/*.json` catalogs are for scripts and `.agents/skills/poke-strategy`; the MCP Worker (`mcp/`, assets from `../public`) loads the minified `public/mcp-catalogs/*.json`.
- Battle engine is centralized in `src/engine/damage.js` (damage formula, delegating move-specific behavior to `src/engine/move-effects.js` and ability/item modifiers to `src/engine/modifiers.js`), `src/engine/speed.js` (the single Speed engine, `speedBreakdown`/`finalSpeed`: Showdown-ordered 4096 chain of Tailwind, Speed abilities, items and the manual modifier, then paralysis; also used by `speed-line.js`), and `src/engine/battle-order.js` (`effectivePriority` for Gale Wings/Prankster/Triage/Grassy Glide + Trick Room). Prefer engine helpers over UI-only patches.
- Shared data helpers: `src/data/catalog.js` (search/sort), `src/data/data.js` (loading), `src/data/pokemon.js`, `src/data/usage-defaults.js` (seeds default moves/items from usage), `src/data/threats.js` (usage-backed opponent sets), the pure builder analyses in `speed-line.js`, `bulk-points.js`, and `break-points.js`, and `src/data/matchups.js` (one-on-one KO race for the matchups page: `matchup()` compares likely hits to KO for both sides, with move order with and without Trick Room deciding equal counts; `observedMatchupSet()` builds usage-backed opposing sets; `trickRoomTeamShares()` reads the team archive).
- Phone set sheet: `src/ui/set-sheet.js` (`mountSetSheet`, `mountSheetBar`, `SHEET_MEDIA_QUERY` = 720px, kept in step with the "Set sheet" section of `src/styles.css`) moves a page's editor element into a bottom-sheet `<dialog>` at phone widths and renders a summary card and a pinned edit bar; Matchups, Builder (closing the sheet applies staged setup edits) and Battle (attacker, defender and field sheets) use it. Desktop layouts are unchanged.
- Shared UI helpers: `src/ui/components.js` (DOM factories: search-result buttons, SP/stage inputs, `STAT_LABELS`, plus the shared sprite fallback, `browserStorage`, Pokémon search matchers and move-slot picker used by every page), `src/ui/bootstrap.js` (`loadCatalogs`, `rankByUsage`), `src/ui/battle-state.js` (pure battle-page state), and `src/ui/builder-state.js` (pure builder state/final stats).
- Data pipeline: `scripts/sync-pokemon-data.mjs` downloads Showdown `.ts` data exports at the commit pinned in `scripts/showdown-pin.json` (parsed by `src/data/showdown-data.js`), overlays the Showdown Champions mod (`data/mods/champions`: legality flags in `champions.legal`/`champions.tier`, Champions learnsets, move/item/ability balance changes) via `src/data/champions-data.js`, plus PokeAPI CSVs (Traditional Chinese aliases, with hand fixes from `src/locales/zh-tw-name-overrides.js` replacing `aliases[0]`; `npm run apply-name-overrides` re-applies them to the committed catalogs without a sync), and writes `public/pokemon.json`, `abilities.json`, `moves.json`, `items.json`. `scripts/sync-limitless-champions-usage.mjs` merges Limitless Champions tournament usage (VGC / M-C format, 50 tournaments) via `src/data/limitless-data.js`. `scripts/sync-champions-spreads.mjs` merges popular SP spreads from Smogon ladder chaos stats (auto-detects latest month + newest Champions VGC regulation, Bo1+Bo3, cutoff 1760) via `src/data/smogon-data.js` into `champions.usage.spreads`. `scripts/sync-ncp-spreads.mjs` merges hand-curated Champions sets from the NCP (Nimbasa City Post) damage calculator's `setdex_ncp-g10.js` via `src/data/ncp-data.js` into `champions.ncp` (`{meta, sets:[{name, spreadName, nature, sps, ability, item, moves}]}`); both spread sources feed the lookup page's "Champions spreads" panel and the battle page's spread dropdowns.
- Sync safety: every sync script fetches through `fetchWithRetry`/`fetchText`/`fetchJson` in `scripts/lib/sync-utils.mjs` (per-attempt `AbortSignal.timeout`, bounded exponential-backoff retries for network errors/429/5xx, Retry-After/RateLimit support, rejects non-OK and HTML responses where data is expected) and fails closed: it validates its own freshly built output with `src/data/catalog-validation.js` (absolute minimums plus at most 25% shrink versus the files it is replacing) and exits non-zero without writing on failure. `scripts/validate-data.mjs` runs all checks (minimums are documented next to `DEFAULT_MINIMUMS`). Showdown `.ts` sources are executed only inside a child Node process started with the permission model (no fs/child-process/worker access, empty env, null-prototype vm context) by `parseShowdownExport`; `test/showdown-data.test.js` proves the old `this.constructor.constructor("return process")()` escape is contained. `sync-champions-spreads` falls back up to 3 months when the newest Smogon month has no Champions formats yet.
- Browser catalogs: `src/data/web-catalogs.js` (pure, browser-safe) owns the Champions selection (`championsEntries`, `includeMegaFamilies`, `includeNamedEntries`) and strips per-generation history keys (`gen1`…`gen8`, `gen7letsgo`, …) from moves/items/abilities; `scripts/build-web-catalogs.mjs` writes the minified results to `public/web/`. `test/web-catalogs.test.js` fails if the committed slim files drift from the full files.
- MCP catalogs: `scripts/lib/mcp-catalogs.mjs` keeps every entry (the MCP reports `legal: false` for non-Champions entries) but drops fields nothing in `mcp/src` or `src/data/strategy-tools.js` and its imports reads (learnsets, per-generation history, long `desc` when `shortDesc` exists, ability/item descriptions and aliases, Champions source/NCP/spread metadata, and all but the top per-Pokémon usage entry the defaults use); `build-web-catalogs` writes them to `public/mcp-catalogs/`. `test/mcp-catalogs.test.js` checks drift and `mcp/test/catalog-equivalence.test.js` checks tool outputs match the full catalogs; if the Worker or engine starts reading a dropped field, update the derivation.
- Translation: after a render, call `translateSubtree(element)` from `src/i18n.js` on the re-rendered element instead of re-translating the whole document; mark containers of third-party text (player/tournament names) with `data-i18n-skip`.
- Tests use Node's built-in test runner (`node --test`) in `test/`.
- Deployment: `.github/workflows/pages.yml` runs `npm test`, `npm run test:mcp`, and `validate-data`, then stages only the browser site (`npm run stage-site` -> `_site/`) and deploys it on push to `main` or when dispatched by `update-data.yml` (never cancels an in-flight deploy). Its `deploy-mcp` job runs `npm run deploy --prefix mcp` after the tests when the `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` secrets exist, and otherwise skips with a warning.

- `src/ui/lookup-page.js` — lookup page controller.
- `src/ui/battle-page.js` — battle calculator page controller.
- `src/ui/battle-state.js` — pure battle-page state helpers (state shape, control updates, calculateDamage input assembly); unit-tested in `test/battle-state.test.js`.
- `src/ui/builder-page.js` / `src/ui/builder-state.js` — builder controller and pure one-Pokémon state/final-stat helpers.
- `src/ui/speed-page.js` / `src/data/speed-line.js` — Speed-tier controller and pure ranking/breakpoint calculations.
- `src/data/bulk-points.js` / `src/data/break-points.js` — defensive and offensive SP breakpoint searches built on `calculateDamage`.
- `test/damage-reference.test.js` / `test/fixtures/damage-reference.json` — roll-for-roll damage checks against `@smogon/calc`; regenerate with `scripts/dev/generate-damage-reference.mjs` (dev-only, `npm install --no-save @smogon/calc@0.12.0` first) instead of hand-editing expected rolls.
- `test/speed-reference.test.js` / `test/fixtures/speed-reference.json` — final-Speed checks against `@smogon/calc` `getFinalSpeed`; regenerate with `scripts/dev/generate-speed-reference.mjs` (same dev-only install).
- These two reference suites are the battle-calculator accuracy record (there is no separate mechanics checklist): treat a mechanic as done only once a reference scenario (or, for Champions-specific behavior `@smogon/calc` lacks, a focused test such as `test/damage-mechanics.test.js`) covers it.
- `test/builder-crosscheck.test.js` — independently assembles builder scenarios against the damage/KO engine to prevent builder/calculator drift.
- `src/engine/damage.js` / `src/engine/speed.js` / `src/engine/battle-order.js` — battle math engine.
- `src/engine/move-effects.js` — per-move registry (`MOVE_EFFECTS`/`moveEffect()`) replacing moveId ladders.
- `src/engine/critical.js` — Showdown crit ratio (`critRatio`/`isGuaranteedCritical`): willCrit moves, and ratio ≥ 4 from high-crit moves plus Leek/Lucky Punch/Scope Lens/Razor Claw/Super Luck/Merciless. `calculateDamage` applies it, and the shared crit toggle shows guaranteed crits pressed and disabled.
- `src/engine/modifiers.js` — per-ability/per-item damage-modifier registry (`ABILITY_MODIFIERS`/`ITEM_MODIFIERS`/`collectModifiers()`).
- `src/data/showdown-data.js` — parses Showdown TypeScript data exports.
- `src/data/champions-data.js` — applies the Showdown Champions mod overlay; `showdownDataBaseUrl`/`championsModBaseUrl` build raw URLs from a `{repo, commit}` pin and refuse anything but a full SHA.
- `scripts/showdown-pin.json` / `scripts/lib/showdown-pin.mjs` / `scripts/bump-showdown-pin.mjs` — the pinned Showdown commit, its loader/validator, and the bump CLI (`npm run bump-showdown`); tested in `test/showdown-pin.test.js` without network.
- `src/data/limitless-data.js` — builds/merges Limitless usage (`LIMITLESS_API_BASE_URL`).
- `src/data/smogon-data.js` — parses/merges Smogon ladder SP spreads (`SMOGON_STATS_URL`).
- `src/data/ncp-data.js` — parses/merges NCP curated Champions sets (`NCP_SETDEX_URL`); the setdex is hand-maintained JS (comments, trailing commas), not strict JSON.
- `scripts/serve.mjs` — minimal static HTTP server bound to 127.0.0.1:4173 (`createStaticServer`; path.relative + realpath containment, no dotfiles, 400 on bad escapes, ETag/Last-Modified/304); tested in `test/serve.test.js`.
- `src/data/catalog-validation.js` / `scripts/validate-data.mjs` — catalog metrics, minimums, max-shrink checks, and the CLI.
- `src/data/web-catalogs.js` / `scripts/build-web-catalogs.mjs` / `scripts/stage-site.mjs` — slim browser catalog derivation, generation, and Pages staging.
- `scripts/lib/sync-utils.mjs` — shared CLI/JSON helpers and the timeout/retry fetch helper.
- `public/*.json` — generated catalogs; do not hand-edit, fix sync/parser code and regenerate.
- `public/web/*.json` — generated slim browser catalogs; regenerate with `npm run build-web-catalogs` whenever `public/*.json` changes (tests enforce it).
- `public/mcp-catalogs/*.json` — generated minified MCP Worker catalogs; regenerated by the same command (tests enforce it).
- `ROADMAP.md` — the completed implementation roadmap and final scope record.

## Conventions & Gotchas

- Plain JavaScript, ES modules, named exports, immutable array/object transforms. Do not introduce dependencies or a build step.
- Do not hand-edit `public/*.json` or `public/web/*.json` unless the task is explicitly about repairing generated output.
- Sync scripts and their tests must never hit the real upstreams in tests; pass a fake `fetcher` (and `directory` for `updatePublicData`/`syncPokemonData`).
- Run the narrowest relevant test group first; run the full `node --test` suite before finishing shared logic, generated data, or cross-page UI changes. For visible changes, verify pages at desktop and mobile widths via `npm start`.
- Label data sources precisely in user-facing copy: Limitless = Champions tournament usage; Smogon ladder stats = SP spreads; NCP (Nimbasa City Post) = curated Champions sets; Pokémon Showdown = mechanics/catalog seed (incl. Champions mod legality/balance); PokeAPI = Traditional Chinese aliases only.
- Default battle mode is doubles; both sides keep four editable moves seeded from top usage when usage data exists.
- Rebuild order matters: run `sync-data`, then `sync-champions-data`, then `sync-champions-spreads`, then `sync-ncp-spreads`, then `build-web-catalogs` when regenerating from scratch (`sync-all` does this). `sync-ncp-spreads` only needs `public/pokemon.json` from `sync-data` and can run at any point after it. The Limitless, Smogon, and NCP merges each preserve the others' data on re-runs. `sync-data` rebuilds catalogs without usage, so run the full chain before committing.
- `.github/workflows/update-data.yml` runs weekly (Mondays 06:00 UTC) as two jobs: `sync` (contents: read, no persisted credentials, no tokens) snapshots `public/` as a baseline, runs the four syncs and `build-web-catalogs`, `validate-data --baseline`, and `test:all`, then uploads `public/` as an artifact; `commit` (contents/actions: write) re-validates the artifact, copies only its JSON/PNG files into `public/`, commits, pushes with rebase-and-retry, and runs `gh workflow run pages.yml` when something was committed (GITHUB_TOKEN pushes do not trigger workflows).
- Engine input is coerced at the boundary: `createField`/`normalizeField` accept weather/terrain aliases (`sun`, `electric`, …), SP/stages are clamped via `normalizeSp`/`normalizeStage` (`calculateStat` stays strict), and `calculateDamage` returns `{ supported: false, reason }` for missing data and a `warnings` array (e.g. SP total > 66) on supported results; `result.ko.chances` lists the cumulative KO chance for each hit count up to 5. Variable hit counts are weighted by `hitCountWeights` (Showdown 35/35/15/15, Loaded Dice, Population Bomb accuracy chain); Speed state flags `transformed` (Quick Powder) and `slowStartActive` default to false/true.
- Showdown is pinned, usage is not: `sync-data` fetches Showdown base data, text, and the Champions mod only from the commit in `scripts/showdown-pin.json` (never `master`); Limitless, Smogon stats, NCP, and PokeAPI are fetched live. `.github/workflows/bump-showdown.yml` (same weekly schedule + `workflow_dispatch`; contents/pull-requests: write) runs `bump-showdown-pin.mjs` and, if master moved, force-pushes `bot/showdown-pin` and opens or edits the single "Bump Showdown pin" PR (compare link in the body); if the pin is already current it closes any stale PR. Merging it pulls Showdown catalog changes into the next weekly sync. Never point the sync back at a branch name.
- Every workflow `uses:` is pinned to a full commit SHA with a trailing `# vX.Y.Z` comment (resolve with `git ls-remote https://github.com/<owner>/<action> 'refs/tags/vX.Y.Z*'`, taking the peeled `^{}` commit for annotated tags); `.github/dependabot.yml` proposes weekly github-actions updates. Never add a tag- or branch-pinned action.
- Repo often has concurrent battle-calculator and data-sync edits; check `git status --short` before editing and do not revert user changes.
